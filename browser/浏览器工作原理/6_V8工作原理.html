V8工作原理（JavaScript的内存机制 ） ​

数据是如何存储的 ​

在js中主要有3种类型内存空间，分别是代码空间、栈空间、堆空间。

  • 代码空间：存储可执行代码
  • 栈空间：也就是调用栈，存储执行上下文，存储对空间地址的引用
  • 堆空间：存储Object类型的数据，提供一个地址让栈空间引用

因为执行上下文需要频繁切换，如果存储太多数据会影响代码执行效率，而堆空间通常能存放很多大的数据

闭包的内存模型 ​

javascript
function foo() { 
  var myName = "jack" 
  let test1 = 1 
  const test2 = 2 
  var innerBar = { 
    setName: function(newName){ 
      myName = newName 
    }, 
    getName:function(){ 
      console.log(test1) 
      return myName 
    } 
  } 
  return innerBar
}
var bar = foo()
bar.setName("smith")
bar.getName()
console.log(bar.getName())

当foo函数执行结束，myName、test1、test2本应该被销毁，但是由于foo返回两个内部函数形成了闭包，所以myName和test1不会被销毁

闭包的创建流程：

  1. 执行到foo函数，创建执行上下文
  2. 编译过程中，遇到内部函数，js引擎对其进行词法扫描，发现内部函数引用了foo上下文中的myName、test1变量，这时js引擎就判断这是一个闭包，于是在对空间创建一个closure(foo)对象，用来保存myName和test1，
  3. 而test2没有被内部函数引用，所以依然在调用栈中

所以只要调用bar.setName、bar.getName，它们的执行的上下文中就包含了closure(foo)

垃圾回收 ​

不再被需要的数据就是垃圾数据，垃圾回收可以释放有限的内存空间

js中的垃圾回收是由垃圾回收器来释放的，不需要手动释放

栈内存的垃圾回收 ​

函数调用结束后，栈内存中的ESP指针向下移动到函数外层的上下文，ESP下移后之前的函数上下文会被标志为无效内存，下一个函数调用时，其上下文就会覆盖这个无效内存

堆内存的垃圾回收 ​

堆内存分两个区域，短时存储和持久存储。短时存储大概1-8M容量，持久存储没有具体限制

堆内存使用垃圾回收器，副垃圾回收器负责短时存储，主垃圾回收器负责持久存储

副垃圾回收器特殊的执行流程

  1. 副垃圾回收器使用 Scavenge 算法，本质就是把短时存储区域分两份：对象区域和空闲区域
  2. 对象区域先存，快存满就执行一次垃圾回收，标记空间中活动对象（正在被使用的）和非活动对象（不再使用的），最后把非活动对象清理掉，活动对象放到空闲区域
  3. 区域翻转：此时对象区域就空了会变为新的空闲区域，原空闲区域就变为了对象区域
  4. 因为复制对象到另一个区域需要时间成本，所以为了效率，短时区域的内存分配会比较小

主垃圾回收器热书的执行流程

  1. 副垃圾回收器经过两次清理还标记为活动的对象会移动到持久存储区域
  2. 一些大的对象会直接被分到持久存储区域
  3. 采用"标记 - 清除（Mark-Sweep）"的算法进行垃圾回收
  4. 遍历调用栈，与调用栈有引用关系的称为活动对象，没有引用关系的就可以判断为垃圾数据。
  5. 清理垃圾数据后会产生大量内存碎片（不连续的内存空间），碎片太多的话就没法分配较大连续的对象，就会出现内存不足，于是产生了另一种算法"标记 - 整理（Mark-Compact）"。
  6. "标记 - 整理（Mark-Compact）"让所有存活的对象向一端移动，把活动对象都存到一起，这样清理后的空间就由碎片变为连续的空间了

全停顿：因为js是运行在主线程之上的，所以执行垃圾回收算法，js脚本会暂停执行，垃圾回收完毕后再开始执行，这就是全停顿

增量标记算法：短时存储较小，所以全停顿影响不大，持久存储可能需要几百毫秒。V8引擎对此进行了优化，叫做增量标记算法：将标记过程分为一个个的子标记过程，再让垃圾回收和js应用逻辑交替进行，直到标记完成，也就是把完整的垃圾回收任务分为很多小人物穿插在js任务中间执行
